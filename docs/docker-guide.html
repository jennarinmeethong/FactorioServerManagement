Docker พร้อมใช้งาน

Factorio Server Manager

คู่มือรัน dashboard และ Factorio dedicated server ใน Docker Compose สำหรับโปรเจกต์นี้

สถานะปัจจุบัน

Dockerfileมี multi-stage build สำหรับ Bun, ASP.NET Core 10 และ runtime image แล้ว
Composeมี service factorio-manager, bind mount ./data และพอร์ตครบแล้ว
ตรวจสอบล่าสุดimage build สำเร็จ, container healthy และ /health ตอบกลับสำเร็จ

สิ่งที่ต้องมี

  • Docker Desktop หรือ Docker Engine ที่รองรับ docker compose
  • พื้นที่ว่างสำหรับ image, Factorio server, saves, mods และ backups
  • พอร์ต TCP 8080 และ UDP 34197 ต้องไม่ถูกใช้งานโดยโปรแกรมอื่น

เริ่มใช้งานอย่างรวดเร็ว

เปิด terminal ที่โฟลเดอร์รากของโปรเจกต์ แล้วรัน:

docker compose up --build -d
docker compose ps
docker compose logs -f factorio-manager

เมื่อเห็นสถานะ healthy ให้เปิด http://localhost:8080

ครั้งแรก: ดูรหัส setup ใน log ด้วยคำสั่งด้านบน รหัสจะอยู่หลังข้อความ first-run setup code แล้วนำไปกรอกในหน้าเว็บ

การตั้งค่าครั้งแรก

  1. คัดลอกรหัส first-run setup จาก log ของ container
  2. สร้างรหัสผ่านผู้ดูแลระบบยาวอย่างน้อย 12 ตัวอักษร
  3. กรอก Factorio username และ token ได้ถ้าต้องการให้ระบบดาวน์โหลด server version หรือ mod จาก Factorio
  4. หลัง setup สำเร็จ ให้เข้าสู่ระบบด้วย username admin

หากต้องการดูเฉพาะรหัส setup โดยไม่ติดตาม log ต่อเนื่อง:

docker compose logs factorio-manager | Select-String "first-run setup code"

พอร์ตและการเข้าถึง

พอร์ตโปรโตคอลหน้าที่
127.0.0.1:8080TCPเว็บ dashboard; ค่าเริ่มต้นเข้าถึงได้เฉพาะเครื่อง host
34197UDPพอร์ต Factorio multiplayer

หากต้องการให้เครื่องอื่นใน LAN เปิด dashboard ได้ ให้แก้ใน compose.yaml จาก 127.0.0.1:8080:8080 เป็น 8080:8080 แล้วจำกัดด้วย firewall และ reverse proxy/TLS ก่อนเปิดสู่อินเทอร์เน็ต

ข้อมูลถาวรและการสำรอง

โฟลเดอร์ ./data ถูก mount เข้า container ที่ /data และเก็บ:

  • ฐานข้อมูล SQLite และ account/configuration
  • Factorio versions, saves, backups, mods และ log
  • credentials ของ Factorio ที่บันทึกไว้ในระบบ

สำรองข้อมูลจาก host ได้โดยหยุด service ก่อนเพื่อความสอดคล้องของไฟล์:

docker compose stop
# คัดลอกหรือ archive โฟลเดอร์ ./data ไปยังพื้นที่สำรองที่ปลอดภัย
docker compose start
อย่า commit data/ เข้า Git เพราะอาจมีฐานข้อมูล, credentials, saves และ backups อยู่ภายใน

คำสั่งดูแลระบบ

# ดูสถานะและ health
docker compose ps
curl http://localhost:8080/health

# ดู log
docker compose logs -f factorio-manager

# หยุด / เริ่ม / restart
docker compose stop
docker compose start
docker compose restart

# อัปเดต image จาก source ปัจจุบัน
docker compose up --build -d

# ปิดและลบ container/network (ไม่ลบ ./data)
docker compose down

การหยุด Factorio server จากหน้า dashboard กับการหยุด container เป็นคนละการทำงาน: ใช้ dashboard ควบคุม process ในเกม และใช้ Docker ควบคุม container

แก้ปัญหาเบื้องต้น

เว็บเปิดไม่ได้

ตรวจ docker compose ps และ docker compose logs --tail 100 factorio-manager หากพอร์ต 8080 ถูกใช้ ให้แก้ port ฝั่ง host ใน compose.yaml เช่น 127.0.0.1:18080:8080 แล้วเปิดที่พอร์ตใหม่

container ไม่ healthy

เรียก curl http://localhost:8080/health และอ่าน log ตรวจว่าระบบ start สำเร็จหรือไม่ จากนั้นลอง docker compose up --build -d อีกครั้ง

Factorio server ดาวน์โหลดไม่ได้

ตรวจ Factorio username/token ในหน้า setup และตรวจการเชื่อมต่ออินเทอร์เน็ตของ Docker host

เปลี่ยนค่าที่กระทบ server ไม่ได้

ระบบตั้งใจบังคับให้หยุด Factorio server ก่อนเปลี่ยน settings, save หรือ mods เพื่อป้องกัน configuration ค้างครึ่งทาง

พัฒนาโดยไม่ใช้ Docker

# terminal 1
dotnet run --project src/FactorioManager.Api --urls http://localhost:8080

# terminal 2
cd src/FactorioManager.Web
bun install
bun run dev

Vite จะ proxy /api และ /hubs ไปยัง backend; หากรันนอก Docker ให้กำหนด DataRoot เป็นโฟลเดอร์ข้อมูลแยกต่างหาก
